# Kenmo型バックテスト

公開されている考え方を依頼された機械条件にした検証です。本人の投資法・成果の完全再現、定性的な企業判断、銘柄推奨ではありません。

## 操作

1. 市場データ画面で銘柄を指定。価格・株式数の差分取得は従来と同じです。Earnings / 財務版を使う場合は決算・財務取得をチェックします。
2. 新規バックテストで戦略を選択。Bottom単独は従来Event Study。Kenmo選択または複数戦略はPortfolio方式になります。
3. 共通の期間・Train/Test・市場・当時時価総額・銘柄を設定。戦略ごとの候補をチェック、詳細設定で売却を比較。候補の積の合計は256以下です。
4. 共通設定で初期資金、最大同時保有数、ベンチマーク、買付・売却手数料とスリッページを設定。費用初期値は既存config.yamlから引き継ぎます。
5. 結果の横並び表はTrain候補を同じTest期間で評価。候補がない戦略は設定ID順の参考値と表示します。表のソートは探索の表示であり、Testからの自動候補選択ではありません。
6. 「曲線・取引」でその設定を選択。未決済は勝率・PFの取引数に含まず、評価損益だけ資産曲線へ反映。CSVは表示条件の取引、全設定、銘柄別品質を取得できます。

## 戦略条件

|戦略|価格版|財務版の追加条件|
|---|---|---|
|Breakout|終値 > 当日を除くN日最高調整高値、出来高 / 当日を除く20日平均 >= 倍率。各条件OFF可|売上YoY、EPSまたは利益YoY、ROE、PER範囲。各条件OFF可|
|Earnings Momentum|報告EPSがある公表済み決算日、決算前終値から反応日終値の上昇率、反応日の出来高倍率|シグナル時点以前に保存された財務スナップショットによる同じ成長・ROE・PER条件|
|Growth|当時時価総額下限以上・上限未満、50日MAより上。成長未確認の価格代理条件|時価総額＋成長・ROE・PER。価格版のMA代理条件は使わない|
|Bottom + Volume|既存の下落率＋出来高、Cooldown|追加なし。比較モードでも既存のN営業日後終値の売却を維持|

Breakout高値候補120/180/252、出来高1/1.5/2、売上5/10/20%、EPS/利益10/20/30%、ROE8/10/15%、PER下限10・上限30/40/50。初期値252、1.5、10%、20%、10%、10〜40。

Earnings初期値反応3%、出来高2倍、2営業日後Entry。1/2/3/5営業日後、反応3/5/10%、出来高倍率を比較。場中（9時〜その日の取引終了時刻）の日時がある場合はその日の終値で反応確定→翌日始値以後。引け後、場外、時刻不明は翌営業日終値で確認→さらに次の始値以後。後者の1営業日後Entryは条件を確定できないので取引なし。休日発表は次の営業日を基準日とする保守的な扱いです。2024-11-05以後の引け15:30、以前15:00を使用。Yahooが付した時間を公表時刻の保証とは扱いません。

Growth初期値50〜300億円、売上10%、EPS/利益20%、ROE10%、PER10〜30。上場経過年数は任意。価格キャッシュ初日を上場日と推測しません。現データソースで信頼できる上場日を保存していないため、上場条件ONは取引なしです。

## 財務とPoint-in-Time

yfinance 1.7.0の公式実装では財務時系列が`asOfDate`（会計期間）を列にして現在取得できる値を返し、公表時刻・改訂前バージョンの履歴を提供しません。公式実装には取得範囲が年次約4年・四半期約5期という制約もあります。

- 財務は年次income statementによる売上YoY、DilutedEPS / BasicEPSを優先したYoY、取れない場合NetIncome YoY。前年分母が正でなければ欠損。赤字から黒字の成長率を任意の大きな値へ置換しません。
- ROE・trailingEPSは取得時点のYahoo情報。年次成長率と同じ会計期間とは限りません。Earningsの個別四半期決算と年次スナップショットの対応付けは保証しません。
- `available_at`を**取得完了時刻**として保存。日付切捨てや決算期末への遡及なし。シグナル日の東京市場引け以前の最新観測だけ後方as-ofで使用。
- 366日より古い観測は失効。PERはその日のRaw Close / 公表済み観測trailingEPS（正値のみ）。観測後に分割があったらEPS単位不明としてPERを無効化。
- データがなければ有効な条件を満たせず無取引。現在値で過去を埋めません。過去の財務版を広く検証するには、別途公表時刻と訂正履歴を持つ財務ソースが必要です。
- 決算日カレンダーは報告EPSがある行だけ利用。将来・予定決算を除外。過去の日時・カレンダーの訂正履歴も完全には復元できず、結果の重大な制約です。Price-only EarningsはEPS値自体による銘柄選択をしません。

参考: [yfinance financials](https://ranaroussi.github.io/yfinance/reference/yfinance.financials.html)、[earnings dates API](https://ranaroussi.github.io/yfinance/reference/api/yfinance.Ticker.get_earnings_dates.html)、[公式financials実装](https://github.com/ranaroussi/yfinance/blob/main/yfinance/scrapers/fundamentals.py)。

## 売却・約定と資金モデル

- 買付はシグナルの翌営業日調整始値。Entry当日の安値も損切りの監視対象。
- 損切り候補5/8/10/15%（初期8%）。固定利確20/30/50/100%、保有20/60/120/252営業日、Trailing10/15/20%、MA5/20/50日。
- Stopと利確はEntry調整始値から計算（手数料込み取得額からではない）。Trailingは**前日までの**最高調整高値から計算。初日はEntry始値を基準にする。
- 始値がStop以下なら始値で売却。始値で利確到達ならその始値。日中High/Lowが両方の水準に達したらStop優先。損切り・Trailingは不利な窓開けをStop価格で埋めない。
- MA割れは当日終値で判断し次の営業日始値。保有N日はEntry日を1日目としたN回の終値保有後の次の始値。固定利確・Trailing・MAにも最大保有日数を設ける（初期252）。Bottom比較の既存売却はEntry+N営業日目の終値で維持。
- 始値売却→始値買付→日中／終値売却→日次評価の順。日中売却による現金をその日の始値買付へ使わない。
- 買付予算は前日終値資産 / 最大保有数、現金上限、借入なし。同一銘柄の重複保有なし。同日シグナルは銘柄コード順。拒否件数（枠・重複・現金）を結果へ保存。
- 買付価格 = 調整始値 × (1+slippage) × (1+buyFee)、売却価格 = 約定調整値 × (1-slippage) × (1-sellFee)。初期費用は既存設定、UIは各率0〜5%を指定可能。
- 端株の理論モデル、配当・分割調整の総収益代理価格。100株単位、現物の配当受取時期、売買停止・値幅制限・板・出来高容量は未再現。表示取引価格は実際の円建て株価ではない。
- 保有中OHLC欠損がある場合、未知の約定を作らず未解決ポジションを残す。欠損日評価は最後の価格を持ち越す参考値。関連CAGR・リスク指標は無効化し品質フラグを表示。

## 期間・指標・時価総額

Train、Test、FULLをそれぞれ初期資金から独立に検証。各期間内のシグナルだけで開始、期間末で強制的な架空約定を作らず評価損益へ反映。未来の「完了取引だけ」を事前選別して資金配分しない。境界取引を削除する既存Event Studyとは区別。

総リターンは終資産 / 初期資産−1、CAGRは252営業日で年率換算、最大DDは初期資産も含む累積最大からの最小下落。Sharpeは日次リターン平均 / 標本標準偏差 × sqrt252、Sortinoは負の日次リターンの2乗平均平方根、無リスク金利0。Calmar=CAGR / abs最大DD。

勝率・平均利益／損失・中央値・Expectancy・平均保有日数・連勝／連敗は決済済み取引のみ。Payoff=平均利益 / abs平均損失、PFは実際の理論資金配分で得た円損益の総利益 / abs総損失。無損失PFは∞参考表示・数値NULL、無取引の勝率などはNULL。上位10%利益依存度は決済取引数の10%（切上げ）の最大利益取引による総利益への比率。

候補選択は最低取引数を満たし価格欠損がなくCAGRを計算できるTrainのみで行う（CAGR→小さいDD→設定ID、上位候補数は既存設定）。CAGRだけを「最良投資モデル」とは表示せず、他の指標・Testを併記。Validation / Walk-Forwardは未実装、期間を変えた独立実行で再検証可能。

区分は既存configの任意の連続区切りを再利用。Micro100億円未満、Small100〜500億、Small Mid500〜1000億、Mid1000〜5000億、Large5000〜1兆円、Mega1兆円以上が既定。ALLは時価総額欠損を含み、指定区分はシグナル時点の区分のみ。Growthの50〜300億条件は既存binと独立に設定可。市場属性は現在のJPXマスター、生存者バイアスあり。

## キャッシュ・拡張

- `data/market/`, `data/shares/`, `data/benchmark/`: 既存の不足期間・差分更新、分割基準変化時の安全な再取得を維持。
- `data/earnings/<ticker>.parquet`: 初回最大100件、通常更新12件を重複統合、1日以内はスキップ。1年以上更新していなければ100件を再確認。Yahooの過去収録範囲は保証なし。
- `data/fundamentals/<ticker>.parquet`: 観測時点を持つ追記スナップショット、7日以内はスキップ。取得は逐次で過剰アクセスを抑える。失敗しても既存ファイルを残す。失敗分再試行に対応。
- バックテストはネットワークなし。銘柄計算は最大4スレッド、Tickerごとに一度準備。候補200万件・曲線1500万行を上限に、過大な探索は明示して停止。Parquetは曲線・取引を分割書込み。
- 共通契約は`src/strategies/base.py`のEntry、Exit、理由、名前・説明、必要データ、パラメータ定義。追加戦略をRegistryへ登録し、`strategy_config`へ設定検証、UIへ条件入力、回帰テストを追加。価格・財務取得や資金配分を戦略内へ複製しない。
- Worker結果: `strategy_results.parquet/.csv`、`strategy_curves.parquet`、`trades.parquet`、`strategy_quality.csv`、`strategy_summary.json`、`run.json`、`summary.md`。設定と結果は既存の不変Artifact保存・リース確認で確定。旧DBスキーマの変更なし。結果APIはDuckDBによる条件付き参照。
